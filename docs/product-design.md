# 校园闲置 MVP

## 目标与非目标
为一所大学的学生提供闲置实物展示、搜索、收藏和线下联系渠道。买卖双方线下完成付款与交付。当前不实现在线商品交易、订单、支付、抽佣、即时聊天、付费置顶或多校运营。

## 核心流程
登录并同意联系方式展示规则 → 上传真实图片 → 填写名称、简介、分类、数量、价格、交付方式和联系方式 → 提交审核 → 管理员通过 → 另一用户搜索浏览并收藏、登录查看联系方式 → 线下交易 → 卖家更新数量或标记已售。

## 页面
- 首页：分类、名称/简介搜索、最新商品、空状态、分页。
- 发布/编辑：1–6 张照片，名称 2–40 字，简介 1–1000 字，数量 1–999，价格 0.01–999999 元，以分存储；自取地点必填；送达说明可选。联系方式明确告知会向登录用户展示。
- 详情：图片、简介、数量、价格、交付方式，收藏，查看联系方式，举报。
- 我的发布：审核状态、编辑、下架、重新送审、已售。
- 我的收藏：收藏和失效状态，支持取消。
- 浏览器管理员后台：待审和公开商品、通过/驳回、违规下架、举报处理。

## 数据与接口
Node.js 24 + Express + SQLite（WAL），本地磁盘图片经 sharp 校验及压缩，生产持久化数据卷。商品图片与独立媒体表关联；上传需登录；修改需所有权。鉴权用随机会话令牌、库中只存令牌哈希。价格不加价。任何商品编辑重新审核；已售和下架不进公开列表。收藏保留失效商品的少量摘要但不泄露已下架详情。
微信原生小程序调用 /api。浏览器预览调用同一真实 API、真实数据库，只有身份可采用本机演示账号。演示数据明确标注，不冒充真实学生内容。校园名称可配置，不宣称完成校园身份验证。

## 验收
两用户测试发布→审核→搜索→详情→收藏→联系方式→已售；验证未登录保护、越权修改、价格精度、必填简介/地点、无效图片、审核前不可见、内容编辑重新审核、已售/下架隐藏联系方式。测试数据与日常数据库隔离。

## 上线条件
微信主体/类目和备案由运营者确认；小程序 AppID、AppSecret、HTTPS 合法域名配置后真机联调；完善真实运营者的用户协议/隐私说明并设置审核人员。生产关闭演示模式并使用独立密钥和管理员密码，定时备份与恢复演练。当前单机部署不提供高可用保证。

## 后续候选
经准入确认的付费置顶、校园身份核验、OSS 存储、自动内容审核、扩展多校。均不属于本期验收。

## 2026-09-17 UI 接入

品牌统一为盒闲。参考“盒闲-手机版UI (3).html”，将五入口移动布局接入真实浏览器业务前台，并同步原生小程序导航、首页轮播、搜索与照片区。“我的”主页与“我发布的”列表区分，收藏及我想要的入口使用同一真实收藏列表。失物、站内消息保留未开放说明，本期不扩展数据库或聊天、反馈接口。发布待审核、所有权与联系方式权限保持不变。

架构和完整接口见 technical-design.md、api.md；原型与真实服务边界见 README.md。
